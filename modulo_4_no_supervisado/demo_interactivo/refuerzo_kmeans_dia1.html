🔬 1. ¿Supervisado vs No Supervisado?

Esta es la distinción más fundamental en Machine Learning. Vamos a entenderla con una analogía antes de tocar código.

🏫 Aprendizaje Supervisado

Como un profesor con las respuestas del examen:

  • 📥 Entrada: características (horas de estudio, asistencia)
  • 📤 Etiqueta conocida: la nota final (A, B, C)

El modelo aprende a mapear entrada → etiqueta.

🎯 Objetivo: PREDECIR etiquetas para datos nuevos

🔍 Aprendizaje No Supervisado

Como un explorador sin mapa:

  • 📥 Entrada: características (presión, caudal, water-cut)
  • ❌ Sin etiquetas: nadie te dice "este pozo es Tipo A"

El modelo descubre patrones ocultos por sí mismo.

🎯 Objetivo: DESCUBRIR estructura en los datos

💡 Regla mnemotécnica: Supervisado = tienes las respuestas (etiquetas). No Supervisado = solo tienes las preguntas (datos), y quieres encontrar patrones.

🎯 2. K-Means: El Algoritmo que Agrupa sin Etiquetas

Imagina que eres un gerente de campo con 50 pozos y quieres saber cuáles se comportan de forma similar. No tienes etiquetas previas. K-Means resuelve esto.

🧩 ¿Qué hace K-Means?

K-Means particiona tus datos en K grupos (clusters) donde cada punto pertenece al grupo cuyo centroide (punto central) está más cercano.

📐 Traducción simple: Es como poner K banderas en un mapa y asignar cada casa a la bandera más cercana. Luego mueves las banderas al centro de las casas asignadas. Repites hasta que las banderas dejen de moverse.

🔄 El Algoritmo Paso a Paso

0. Datos Crudos 1. Inicializar K=3 centroides 2. Asignar cada punto 3. Recalcular centroides 4. Repetir hasta converger ✅ Resultado Final
Paso 0: 200 puntos de datos sin etiquetar. Cada punto = un pozo con 2 variables (presión y caudal).
🔑 ¿Cuántos clusters (K) elegir? ¡No se adivina! Más adelante veremos el Método del Codo y Yellowbrick para elegir K de forma científica.

🤔 ¿Por qué en este ejemplo solo usamos 2 variables (WHP, Qo) y no todas?

En el Día 2 (DBSCAN) trabajamos con telemetria_anomala.csv, que solo tiene 2 columnas numéricas: WHP_psi y Qo_bpd. Es un dataset diseñado para detectar anomalías en un solo pozo a lo largo del tiempo.

En el Día 1 (K-Means), en cambio, usamos pozos_clustering.csv con 50 pozos y 7 variables. Ahí K-Means sí agrupa usando todas las dimensiones.

🧠 La regla: Tú le das a K-Means la lista features = ['Qo','Qw','Qg','WHP','BHP','Water_Cut','GOR']. El algoritmo usa TODAS. Cuantas más variables relevantes le des, mejor será la agrupación. Pero recuerda: ¡siempre escala primero!

📏 3. La TRAMPA de NO Escalar — Mira la Diferencia

Desliza la barra de abajo para transicionar entre datos crudos (sin escalar) y datos transformados con Z-Score. Mismos datos. Mismo K-Means.

🔴 SIN ESCALAR: Caudal (0-2000) aplasta al Water-Cut (0-1). K-Means divide en franjas verticales — solo ve Qo.
⚠️ Regla de Oro: Sin StandardScaler(), K-Means NO SIRVE. Una variable numéricamente grande (2000 bpd) domina a una pequeña (0.25 water-cut). Al escalar, todas pesan lo mismo.

📐 La Fórmula Z-Score explicada

z = (x − μ) ÷ σ
SímboloSignificadoEjemplo con Caudal (Qo)
xValor original del datoUn pozo produce 2000 bpd
μ (mu)Media de TODOS los datosLa media de Qo es 1500 bpd
σ (sigma)Desviación estándarσ = 500 bpd
zValor transformadoz = (2000−1500)/500 = +1.0

Interpretación: Un z-score de +1.0 significa "1 desviación estándar por encima de la media". Todas las variables quedan en la misma escala. 🎯

🟡 6. Yellowbrick: Eligiendo K con Ciencia

Elegir el número de clusters NO es adivinanza. Yellowbrick nos da el Método del Codo.

📐 ¿Qué es la INERCIA? (El concepto MÁS importante del método del codo)

La inercia es un número que mide qué tan "apretados" están los clusters. Se calcula así:

Inercia = Σ (distancia de cada punto a su centroide)²

En palabras simples: Para cada cluster, mido qué tan lejos está cada punto de su centro (el centroide). Elevo esa distancia al cuadrado. Sumo todo. Ese número es la inercia.

🔴 Inercia ALTA (mala)

Los puntos están lejos de sus centroides. Clusters "flojos", dispersos, poco cohesionados.

Ej: K=1. Todos los puntos en un solo cluster gigante. La inercia es enorme porque el centroide está lejos de todos.

🟢 Inercia BAJA (buena)

Los puntos están cerca de sus centroides. Clusters compactos y bien definidos.

Ej: K=50 (tantos clusters como puntos). Cada punto ES su propio centroide. Inercia = 0. Pero no sirve de nada.

⚠️ El dilema: Más clusters (K más grande) siempre reducen la inercia. Pero llega un punto donde agregar otro cluster apenas mejora nada. Ese punto es EL CODO — el balance perfecto entre pocos clusters (inercia alta) y muchos clusters (inercia baja pero inútil).

📉 Método del Codo (Elbow Method) — Gráfico Interactivo

Mueve el cursor sobre los puntos para ver valores. El "codo" está en K=3 — agregar más clusters no reduce significativamente la inercia.
🧠 ¿Cómo leer el codo? Donde la curva hace un quiebre brusco (como un brazo doblándose). A partir de ese punto, agregar más clusters da beneficio marginal.

🐍 Yellowbrick en 1 línea

# En lugar de codificar el codo a mano... from yellowbrick.cluster import KElbowVisualizer from sklearn.cluster import KMeans model = KMeans(random_state=42) visualizer = KElbowVisualizer(model, k=(1,10)) visualizer.fit(X_scaled) visualizer.show() # ¡Yellowbrick dibuja el codo y marca el K óptimo automáticamente!

Yellowbrick prueba K=1 hasta K=10, calcula la inercia para cada uno, dibuja la curva, y marca con una línea vertical el K óptimo. Todo en 4 líneas.

💻 7. K-Means en Python: Código Explicado Línea por Línea

Aquí está el flujo completo que usamos en el Día 1. Cada línea tiene su explicación al lado.

# ─── PASO 1: Importar librerías ─── import pandas as pd # Manejo de DataFrames (tablas) import numpy as np # Operaciones matemáticas y arrays from sklearn.preprocessing import StandardScaler # ← EL ESCALADOR Z-Score from sklearn.cluster import KMeans # ← EL algoritmo de clustering import matplotlib.pyplot as plt # Gráficos import seaborn as sns # Gráficos estadísticos bonitos # ─── PASO 2: Cargar datos ─── df = pd.read_csv('pozos_clustering.csv') # Lee el CSV → DataFrame con 50 pozos # ─── PASO 3: Definir FEATURES (las columnas que K-Means usará) ─── features = ['Qo_bpd', 'Qw_bpd', 'Qg_mscfd', # 💡 CADA columna = UNA dimensión 'WHP_psi', 'BHP_psi', # 💡 5 features = espacio ℝ⁵ 'Water_Cut', 'GOR'] # 💡 7 features = espacio ℝ⁷ # ─── PASO 4: ¡ESCALAR! (CRÍTICO) ─── scaler = StandardScaler() # Crea el objeto escalador (aún no hace nada) X_scaled = scaler.fit_transform(df[features]) # .fit(): calcula μ y σ de cada columna # .transform(): aplica z = (x-μ)/σ # Resultado: array con media=0 y std=1 # ─── PASO 5: Elegir K con Yellowbrick ─── from yellowbrick.cluster import KElbowVisualizer model = KMeans(random_state=42) # random_state = semilla fija (reproducible) viz = KElbowVisualizer(model, k=(1,10)) # Prueba K=1,2,3... hasta K=10 viz.fit(X_scaled) # Ejecuta K-Means 10 veces y dibuja el codo viz.show() # Muestra el gráfico con K óptimo marcado # ─── PASO 6: Entrenar K-Means con el K elegido ─── kmeans = KMeans(n_clusters=3, # K=3 clusters (elegido del codo) random_state=42) # Misma semilla = mismos resultados df['Cluster'] = kmeans.fit_predict(X_scaled) # .fit(): entrena | .predict(): asigna # Cada fila recibe 0, 1, o 2 # ─── PASO 7: Ver resultados ─── print(df['Cluster'].value_counts()) # ¿Cuántos pozos en cada cluster? print(df.groupby('Cluster')[features].mean()) # Perfil promedio de cada grupo

📋 8. Recap: Lo que DEBES Recordar

✅ Sí

  • Escalar SIEMPRE antes de K-Means
  • Cada columna en features = una dimensión
  • K-Means usa TODAS las dimensiones
  • Usar Yellowbrick para elegir K
  • El cluster es info NUEVA, no reemplaza al Pozo

❌ No

  • NO uses K-Means sin escalar
  • NO adivines K "a ojo"
  • NO confundas "ver 2D" con "calcular en 2D"
  • NO pienses que el cluster borra la columna Pozo
  • NO uses K-Means si tus clusters no son esféricos (→ DBSCAN, Día 2)
